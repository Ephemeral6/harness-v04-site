World —— 一帧里看得见的这一局的全部状态。

每个字段一件事。每个字段为什么删不掉，写在 analysis/<字段>.txt，
那里有分离表的见证（哪两帧只差这一位）和消融读数（抹掉它哪几条规则的判决会变）。

    phase     格阵的相位（像素 → 格）。只有一处用得上：点击给的是像素坐标
    walls     墙格：谁都挡（色2，以及画面之外）
    bands     带格：挡被操纵的那一块；被推 / 被扫的东西停不住，会滑出去
    slots     框：内部那一片格
    pieces    会被推的块（带壳的 + 裸的），按格集合排序
    selected  被操纵的那一块（它的左上角那一格）；帧上没有被操纵的块时 None
    retired   被点走过的块（核心色4）的左上角。从没被选中过的（核心色5）不在里面
    gates     门带
    bar       预算条上还剩几格

## 帧上读不出来、因此不在这里的三样

    门带数到 0 那一帧朝哪头长      Gate.sign = None，见 movable/gate.py
    这一关已经走了几步            预算条是它的一个取整后的函数，同一个格数对应一两个步数
    这一关的预算总共有多少步        帧上只有条，没有分母

它们是模型（lean2/）那一层的隐藏状态，在那里写成明处的假设或整关口径；
这里一位都不补：补了就是给世界加一位帧上没有的信息，而判据会悄悄去读它。

字段 phase · 为什么删不掉

1. 它记的是什么：格阵的相位（像素 → 格的换算原点，每一关一个）。
2. 谁读它：只有点击那一支——derive/advance.click_cell 把 ACTION6 的像素坐标换成格（click_selects；
   level_solved 在点击步上经 after 间接用到它）。
   Lean 那边是 Board.pr / pc，Rule/Move/ClickSelects.lean 的 clickCell 读它。
3. 抹成常量会变的判决：见上面装置那一段（抽样分母里点击步很少，所以变的处数小）。
4. 分离表说分不开（field_split.txt：同组里只见过 1 个值）。和第 2、3 句对得上的解释是：
   这批语料里版面整关一起换——相位、墙、带、框在同一步（换关）上一起变，从不单独变。
   这不是「写法重复」：规则分开读它们（相位只给点击用，墙挡一切，带只挡被操纵的那一块，框只给过关用）。
   能把它们分开的实验：同一张版面整体平移一个像素（相位变、别的不变）——这一局 7 关里没有，记成欠账。
   判定：留着。删掉它，同一个像素点击会落到不同的格上，点中的块就不一样。

字段 walls · 为什么删不掉

1. 它记的是什么：墙格——谁都挡（色2 的格，外加画面之外一圈）。
2. 谁读它：mover_steps（前面那一排是墙就不动）、push_shoves / gate_strikes（slide / make_way 撞墙即停，
   in_front 中间隔着墙就扫不到）、board_static（逐步核它不变）。Lean：Board.walls（位图）。
3. 抹成常量会变的判决：见上面装置那一段——处数很大，有规则在用。
4. 分离表说分不开，和第 3 句不一致——解释同 phase.txt：墙、带、框、相位在这批语料里只在换关那一步
   一起换，没有一对世界只差墙。它们不是同一件事（规则分开读），所以不合并；
   「同生共死」在这里是语料的形状（每关一张版面），不是对象的冗余。

字段 bands · 为什么删不掉

1. 它记的是什么：带格（色15）——挡被操纵的那一块；被推 / 被扫的东西停不住在上面，会一路滑出去。
2. 谁读它：mover_steps（前面是带就不动）、push_shoves / gate_strikes（slide / make_way 的「滑出带」那一段，
   in_front 中间隔着带就扫不到）、board_static。Lean：Board.bands。
3. 抹成常量会变的判决：见上面装置那一段。反向测试里 band_passable（带子不挡被操纵的那一块）
   和 no_band_slide（被推的东西停在带上也不滑）两个突变体都红了——两种用法各自有人读。
4. 分离表说分不开，理由同 walls.txt（版面整关一起换）。
   为什么不和墙合并（判据 7 分化）：墙和带对「被推的东西」一个挡一个不挡，规则正在用这个差别；
   合成一个「阻挡格」之后，slide 里就得再写一个 if 去认颜色——那正是「对象少了一位」的账单。

字段 slots · 为什么删不掉

1. 它记的是什么：框——每个框内部的那一片格。
2. 谁读它：只有 level_solved（derive/seated.all_seated：每一块占的格 == 某个框的内部，块和框一样多）。
   Lean：Board.slots，Rule/Outcome/LevelSolved.lean。
3. 抹成常量：上面装置那一段在「普通步抽样」分母上是 0 处——因为普通步上谁也没嵌满，
   不管框在哪都判「没过关」。第二个分母（换关那 31 步，readings.json 的 levelup_fields）上它会变：
   那几步正是「块嵌进框里」的那一步，框挪了位置就判不出过关。
   这就是「消融分母不含那一类步」的典型：只看第一个分母，它会被报成「没人用」。
4. 分离表说分不开（版面整关一起换，同 walls.txt）。三个读数合起来：点得出读者（level_solved），
   第一个分母上消融不变、第二个分母上变——对得上，留着。

字段 pieces · 为什么删不掉

1. 它记的是什么：会被推的块（带壳的 + 裸十字），每块是它占的那几格，外加「带不带壳」。
2. 谁读它：几乎每一条——mover_steps / push_shoves / gate_strikes / click_selects（整张表），
   level_solved（嵌没嵌好），gate_ticks / gate_keeps_heading（门带位置按推完的表认）。
3. 抹成常量会变的判决：见上面装置那一段（最大的一档）。
4. 分离表说分得开（见证：field_split.txt 里 pieces 那一行的两帧，只差一块的位置）。三者对得上。
   判据 6 归并：带壳块和裸十字放进同一个类，因为推、扫、让开、嵌进框走的是同一套规则；
   判据 7 分化：它们唯一被规则用上的差别是「能不能被点中」，那一位就是 Piece.shelled
   （反向测试 bare_clickable：让裸十字也点得中，click_selects 当场红）。

字段 selected · 为什么删不掉

1. 它记的是什么：被操纵的是哪一块（它的左上角那一格）。帧上是核心色0 的那一块。
2. 谁读它：mover_steps / push_shoves（谁挪、谁是推手、谁不让开）、click_selects（换没换）、
   gate_strikes（me_key：帧上没有被操纵的块时不开口）。Lean：St.sel。
3. 抹成常量会变的判决：见上面装置那一段——处数很大。
4. 分离表说分得开（见证：同一张盘，只是被操纵的换了一块）。三者对得上，留着。

字段 retired · 为什么删不掉

1. 它记的是什么：被点走过的块（核心色4）。从没被选中过的块核心是色5，不在这里面。
2. 谁读它：只有 click_selects——它断言点走之后原来那一块进 retired、新点中的那一块出来。
   推、扫、过关、预算，没有一条读它。Lean：Piece.retired，只在 proj 里和观测比。
3. 抹成常量会变的判决：见上面装置那一段（全在 click_selects 上）；反向测试 no_retire 红在 click_selects。
4. 分离表说分得开（见证：同一张盘，只差一块的核心是色4 还是色5）。三者对得上。
   卡 06 的问题：删得掉吗？ 按判据 1（少记这一位，玩法还能不能正确运行）——玩法照样运行：
   它是一位纯显示的信息，没有任何一条管「怎么走 / 算不算赢」的规则读它。
   留着的理由只有一个，而且写在明处：模型要逐帧对上观测（每关那一层比块的核心颜色），
   删掉它就得让判据不看核心颜色——那是把判据放松一位来迁就对象，不是简化。
   判定：留着，身份记成「显示位」，页面上写明它不影响玩法。

字段 gates · 为什么删不掉

1. 它记的是什么：门带——占哪几格、朝哪头长（数到 0 时读不出，记 None）、数到几。
2. 谁读它：gate_ticks（拍数）、gate_strikes（归零那一拍扫谁）、gate_keeps_heading（朝向）、
   mover_steps / push_shoves（门带也在整张表里：会被推、会挡推手）。Lean：St.gates。
3. 抹成常量会变的判决：见上面装置那一段。
4. 分离表说分得开。三者对得上。
   判据 7 分化 / 6 归并：门带和块都会被推、都在「整张表」里，但门带不进「嵌没嵌好」、
   它自己数拍子会扫人——所以是另一个类，不并进 Piece。
   一位被删掉的：Gate 起初有 layers（一圈几层）这个字段；它由「格数 + 朝向」算得出来（沿生长方向的像素层数），
   不是独立的信息，删了，改成 derive/gate_clock.layers。这一刀是写代码时凭定义砍的，当时没跑分离表留见证
   ——卡 06 重取时它已经不是字段，量不到了；这里照实记下。

字段 bar · 为什么删不掉

1. 它记的是什么：预算条上还剩几格。
2. 谁读它：bar_ticks（前后两帧的格数对得上某个已走步数）、bar_empty_ends（走空 ⇔ 判负）。
   Lean：不是 St 的字段——St.used（已走几步，隐藏）才是，条的格数由 proj 用 barOf 算出来和观测比。
3. 抹成常量会变的判决：见上面装置那一段。
4. 分离表说分得开（见证：同一张盘，只差条上一格）。三者对得上。
   帧上读不出、因此不在这里的那一位：这一关已经走了几步。条是它取整后的函数（一格对应一两步），
   所以世界只记条；「走了几步」在模型那一层是隐藏状态，每关从 0 数起，由逐帧核对去核。

# World —— 世界 = 不动的那一半（Board）+ 会变的那一半（St）
（对应 `objects/world.py`）

Python 的 `World` 是一帧里看得见的全部。这里拆成两块：

    Board   墙、带、框、格阵相位、这一关的预算总步数 —— 一关之内一格都不变
    St      块、被操纵的是哪一块、门带、这一关已经走了几步

**`step` 只拿到 `St`，`Board` 是只读的参数**——于是「走一步版面不变」在模型里
**表示不出来**，不用证（它在语料上站不站得住，由 Python 的 `board_static` 逐条核）。

## St 比帧上看得见的多两位

    used           这一关已经走了几步。帧上只有预算条（它的取整函数）
    Gate.dir       数到 0 的门带朝哪头长

这两位是**隐藏状态**。判据只比帧上看得见的那部分（`Obs/Check.lean` 的 `proj`），
隐藏的两位怎么来的写在 `Obs/Replay.lean` 的文件头：前者从开局的 0 起数，
后者取整关口径。

## 墙和带用位图存

`walls.getD r 0` 是第 r 行的位图，第 c 位是 1 就是墙。内核算 `testBit` 走的是大数运算，
比在几百个格的表里挨个比快得多——这一局每关要让内核逐步算一百多步。
-/
import Obj.Geometry.Cell
import Obj.Board.Slot
import Obj.Movable.Piece
import Obj.Movable.Gate


structure Board where
  walls  : List Nat
  bands  : List Nat
  slots  : List Slot
  pr     : Nat
  pc     : Nat
  budget : Nat
deriving Repr

structure St where
  pieces : List Piece
  sel    : Nat
  gates  : List Gate
  used   : Nat
deriving DecidableEq, Repr

/-- 世界 = 不动的那一半 + 会变的那一半（Python 那边的 `World` 是一帧里看得见的这两半）。 -/
abbrev World := Board × St

def Board.isWall (b : Board) (x : Cell) : Bool := (b.walls.getD x.r 0).testBit x.c
def Board.isBand (b : Board) (x : Cell) : Bool := (b.bands.getD x.r 0).testBit x.c

from __future__ import annotations

from dataclasses import dataclass

from .board.slot import Slot
from .geometry.cell import Cell
from .movable.gate import Gate
from .movable.piece import Piece


@dataclass(frozen=True)
class World:
    phase: tuple[int, int]
    walls: frozenset[Cell]
    bands: frozenset[Cell]
    slots: frozenset[Slot]
    pieces: tuple[Piece, ...]
    selected: Cell | None
    retired: frozenset[Cell]
    gates: tuple[Gate, ...]
    bar: int

    # ---- 只读的便利：不引入新信息，只是换个取法 ----
    def piece_at(self, anchor: Cell | None) -> Piece | None:
        if anchor is None:
            return None
        for p in self.pieces:
            if p.anchor == anchor:
                return p
        return None
