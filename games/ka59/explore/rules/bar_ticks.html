它说什么

第 L 关总共 BUDGET[L] 步；走了 u 步时条上剩 round↓(64·(B−u)/B) 格（恰好 .5 往下舍）。每个非 RESET 动作（包括点击、包括推不动的方向动作）走一步。

它明确不主张什么

  • B 从哪来：帧上没有，是拟合的；第 1、3 关 127 / 128 分不开
  • 这一关已经走了几步：帧上读不出（同一个格数对应一两个步数），所以这条只断言「存在一个 u 使前后两帧都对上」——比「每步扣 0 或 1 格」强，比「知道 u 之后逐步定死」弱；逐步定死的那一句在模型里（每关的逐帧核对）
  • RESET / 换关之后条补满：换关那一步不归它；RESET 归 reset_restores

B 帧上读不出，是拟合的常数，住在 `Board.budget`（导出器写进去，出处在 `Obs/Replay.lean` 文件头）。

def bar_of(B: int, u: int) -> int:
    """走了 u 步时条上剩几格：64·(B−u)/B 四舍五入、恰好一半往下舍。"""
    x = FULL * (B - u)
    return (2 * x + B - 1) // (2 * B)


def scope_(prev, action, nxt, ctx=None):
    if action == "RESET":
        return "RESET → reset_restores（条补满）"
    r = same_level(ctx)
    if r:
        return r
    if ctx["level_prev"] not in BUDGET:
        return "这一关没有拟合出总步数"
    return None


def assert_(prev, action, nxt, ctx=None):
    B = BUDGET[ctx["level_prev"]]
    a, b = world(prev).bar, world(nxt).bar
    return verdict(any(bar_of(B, u) == a and bar_of(B, u + 1) == b for u in range(B + 1)))
