明写的缺口（5 条）——摆在最上面，没藏

  • RESET 不是模型里的动作：每一句「走不通」的准确意思是「不经过重来就走不通」（Proof/Reachable.lean 文件头）
  • 计数条不进模型，也就没有「吃满」那一支；语料里计数条最多吃到 40 格（共 64 格），「预算见底会怎样」这批语料说不了
  • 朝向（Python 的 Glyph）不进模型：模型只到形状为止；朝向那条规则只在 Python 一侧判（orient_kept）
  • 「重来一次放回开局」这条假设在认证段里没有出场（段内没有重来），这批语料没有给它被驳倒的机会
  • 两张「走不通」的盘是手造的教学盘（第 0 关开局只改一处），不是语料里的局面：六关在语料里全过了

屏幕上有三样东西：一行「题面」、一本「图例」、一行「答题条」。 图例里每一条都是一句改写规则：这几个字形 → 换成那几个字形。

把题面按图例一段一段改写（有的关要连着改几轮，颜色一环接一环），改出来的那一串就是答案。 让答题条和答案逐格同形，这一关就过了。同形 = 形状一样，朝向不论（转过、翻过都算）。

每个字形都在一个 7 格的环上：按一下它就换成环上的下一个（或上一个）形状。 前几关你拨的是答题条；后两关答题条是死的，你拨的是图例本身——把规则改到能把题面改写成答题条为止。

你能做的只有四件事

  • ACTION4 / ACTION3——黄框（焦点）走到下一站 / 上一站，走到头绕回另一头。 答题条关里一格一站；图例关里每条规则的键串、值串各一站。
  • ACTION1 / ACTION2——黄框框住的那一串里，每一个字形在自己的环上进一格 / 退一格。

没有墙，只有两种关和一条计数条

答题条关第 0、1、2、3 关：焦点在答题条上，图例一格都动不了。
图例关第 4、5 关：焦点在图例上，答题条一格都动不了。一关之内焦点从来不换种类。
计数条最底下那一行，每走几步从右端吃掉一格（几步一格因关而异）。 这批语料里它最多吃到 40 / 64 格，从没吃满——吃满会怎样，这一份说不了（见上面的缺口）。
