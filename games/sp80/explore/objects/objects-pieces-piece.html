为什么删不掉它（analysis/Piece.txt）

Piece —— 件（objects/pieces/piece.py）

1 它记的是什么：一件占的格（含记号格）、其中的记号格（marks）、没选中时画 15（拐件）还是 8（直件）（bent）。
  World.pieces 的**顺序**也是件的一部分信息：后画的压在上面，最后一件是选中件。
2 谁读它：方向键两条（选中件挪不挪、挪到哪）、点击两条（包围盒命中）、水流（件格挡水、同一连通块的内角出射流、
  记号出水）、放下的颜色、交棒。
3 逐位抹（run_rules.py --reverse 的 reverse_subfields）：
     bent 全抹成直件      1 处（deselected_rest_color_by_shape）
     marks 全抹成空       5 处（fire_wins_iff_all_mouths_fed）
     选中是谁 + 叠放次序   938 处
4 分离表：pieces 整体分得开（见 World.txt）。

**三个读数对不上的那一处：bent 只变 1 处。** 原因是消融的口径：它在前后两帧上同时抹，
规则比的是「前一帧画出来」与「后一帧画出来」——两边一起抹成 8，比出来照样相等。
这正是卡 06 说的「扰动太温柔」的一种：扰动在比较的两侧对称，读数上和「没人读」一样。
真正会被 bent 打红的是**拿模型的画和帧比**的那一层：Lean 的 traceOk 拿模型自己算出来的件去画、
和帧上读到的颜色比，第 4、5 关的拐件在帧上是 15——抹成直件，那两关的逐帧核对第一次放下拐件就对不上。
（跑过了：lean2/mutate.py 的 L1「放下的件一律画直件色」——在 lean2 的副本里把 restBent 改成恒 false，
Obs/Corpus.lean 的 corpus_no_false / corpus_yes 当场编不过（内核判出矛盾）。mutate 在第一处红就停，
所以 L4/L5_trace 在这个突变体下没有单独编；红在逐条那一层已经足够说明 bent 被读。）

最大的一笔欠账（卡 06「拆」）：**件会互相压住，被压住的那一截帧上读不出来**，并排贴着的两件同色时边界也看不见。
解析给的是「可见分解」：选中件（永远画在最上面、整件可见）+ 每一块同色连通块算一件。
本批语料 371 行里 36 行有件被压住或并排（可见件数或件格数少于本段本关开局）。
  · 规则层：点击那条与「腾出来的格露出空地」那条在这 36 行上不开口（有名字的不管理由，计数进读数）；
  · 模型层：Lean 的件从一关开局起带着**整件**走，那 36 行里被揭开的格全部算对（Proof/Levels.lean 第 4、5 关）；
  · 逐条那一层（Obs/Corpus.lean）从帧重新起算时拿到的只是可见分解，12 步对不上，按纤维口径记「说不出话」，不记「错」。
一步能把可见分解和整件分开的实验：没有——帧上就是读不出被压住的那一截。所以它不是「语料不够」，
是**观测比世界少一位信息**，只能由带状态的那一层补。

「放下时画 8 还是 15 由形状定」是一条规则（deselected_rest_color_by_shape），不是件的定义：
解析把**读到的**颜色存进 bent（未选中件），把选中件的 bent 按形状填——
被压住一角的拐件在帧上可能只露出一条直线，这时 bent 还是 15，形状读法会错；所以 bent 存读到的，不从形状算。

它是什么（objects/pieces/piece.py 的文件头）

`Piece` —— 一件**件**：一小块刚体，玩家能选中它、挪它；水撞上它会拐弯。

一句话：一件 = 它占的逻辑格（`cells`）+ 其中嵌着记号的那几格（`marks`，画成发射器色4）
+ 它是直的还是拐的（`bent`）。

**颜色不是件的属性，是它此刻的状态画出来的样子**：
    被选中的那一件整块画成色9；
    没被选中时，直件（只占一行或只占一列）画成色8，拐件（既跨行又跨列）画成色15；
    记号格不论选没选中都画成色4。
「没选中时画成哪种色」由形状定，这是一条要被判错的规则
（`rule/世界怎么回应/rest_color_by_shape.py`），所以这里把 `bent` 存成**读到的**那一位，
不从形状算——算出来的话那条规则就永远不会错了。

它为什么删不掉：水流的每一次拐弯都看「脚下这一格是不是件、左右两格是不是**同一件**」
（`derive/flow.py`）；点击选中的是「包围盒罩住点击格的那一件」（`derive/hit.py`）。
这两句话都要件的**身份**，只有格的颜色说不出来。（见 `analysis/Piece.txt`。）

一件可能有一部分被别的件压住——那几格帧上读不出来。解析只读得到**可见的那部分**；
带着状态从一关开局往下走的时候，模型手里的是整件。两者的差别是这一局最大的观测缺口，
写在 `analysis/Piece.txt`，不在这里藏。

它的 Lean（Obj/Pieces/Piece.lean，身份：定义）

/-
# Piece —— 件（对应 `objects/pieces/piece.py`）

一件 = 它占的格（含记号格）+ 其中的记号格 + 没选中时画成拐件色（15）还是直件色（8）。

颜色不是件的属性，是状态画出来的样子：选中件画 9，记号格画 4——那是 `Obj/Composite/Render.lean` 的事。
-/
import Obj.Board.Grid

namespace Game

structure Piece where
  cells : List Pos
  marks : List Pos
  bent : Bool
deriving DecidableEq, Repr

def Piece.shift (pc : Piece) (f : Pos → Pos) : Piece :=
  ⟨pc.cells.map f, pc.marks.map f, pc.bent⟩

def Piece.rowMin (pc : Piece) : Nat := pc.cells.foldl (fun a p => min a p.row) 1000
def Piece.rowMax (pc : Piece) : Nat := pc.cells.foldl (fun a p => max a p.row) 0
def Piece.colMin (pc : Piece) : Nat := pc.cells.foldl (fun a p => min a p.col) 1000
def Piece.colMax (pc : Piece) : Nat := pc.cells.foldl (fun a p => max a p.col) 0

/-- 包围盒罩不罩住这一格。 -/
def Piece.boxHas (pc : Piece) (p : Pos) : Bool :=
  pc.rowMin ≤ p.row && p.row ≤ pc.rowMax && pc.colMin ≤ p.col && p.col ≤ pc.colMax

/-- 只占一行、或只占一列。 -/
def straight (cs : List Pos) : Bool :=
  match cs with
  | [] => true
  | p :: rest => rest.all (fun q => q.row == p.row) || rest.all (fun q => q.col == p.col)

end Game
