1 它记的是什么：一关之内一格都不会动的东西。卡 03 由原来四个字段（grid / walls / cups / sources）合成。

4 分离表：**分不开**——741 帧里找不到一对「只差版面」的世界。
  这是**欠账，不是该删**，三种可能里是第 ③ 种的一个变体：版面只在换关那一刻变，而换关时件表也一定跟着换。

它是什么（objects/world.py 的文件头）

`World` —— 这一局一帧的**全部状态**。字段就是对象。

每个字段为什么删不掉，写在 `analysis/<对象>.txt`；「抹掉它，哪一对局面从能区分变成不能」
的见证由 `ledger/field_split.py` 在语料上真找，读数进 `analysis/field_split.txt`。

    board     版面（格盘、墙、杯、发射口）—— 一关之内不动；卡 03 由四个同生共死的字段合成
    pieces    件，按画的先后排；**最后一件是被选中的那一件**
    hud       预算条还亮着几像素（色14 的个数，满格 64）

**不在这里的东西**（都是故意的）：
  · 关卡号、局面状态（NOT_FINISHED / WIN）——上游 API 给的，规则要用从 ctx 读；
  · 本关预算 B（30/45/100/120…）——帧上读不出，只读得出剩余的**比例**；它是按关的常数，从 ctx 读；
  · 本关已经走了几步 k ——帧上只读得出 64-round(64k/B)，B>64 时一个读数对应两个 k；
  · 被压在别的件底下的那几格 ——帧上读不出（见 `analysis/Piece.txt`）。

# World —— 一个局面的全部**会变**的状态（对应 `objects/world.py`）

    pieces   件，按画的先后排；**最后一件是选中件**
    k        本关已经走了几步

和 Python 那一份差在两处，都是故意的：

  · 版面（`Board`）不在这里——它不会变，放进状态就得证「走一步它不变」；放在外面，这句话表示不出来。
  · Python 存的是 `hud`（帧上读到的亮着几像素），这里存的是 `k`（走了几步）。
    **按世界写，不按观测写**：B>64 的关一个 `hud` 读数对应两个 `k`，拿 `hud` 当状态就算不出下一步；
    `hud` 是 `k` 画出来的样子（`Obj/Composite/Ladder.lean`）。开局 `k = 0`（满格只对应这一个 `k`）。
-/
