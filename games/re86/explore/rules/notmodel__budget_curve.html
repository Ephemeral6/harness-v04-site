它说什么

关内第 n 步走完时 spent = ⌊64·n/B + 1/2⌋，B 是这一关的预算常数。

HUD「已花掉」= round(64·n / B)：n 是这一关已经走了几步，B 是这一关的预算（每关一个常数）。

论域：换关 / 终局 / RESET → hud/tick；ctx 里没有 n 或 B → 不管

它明确不主张什么

  • B 是**拟合**的：run_rules.py 在每关所有段上找使全部读数成立的整数 B（找不到就是 None，这条就闭嘴）。所以「判错 0」的含义是「每关存在这样一个 B」，而不是「B 是量出来的」
  • 预算花光（n = B）之后会怎样：语料里 0 次

改版史

  • v1 册子 spent_resets_on_levelup 的 NOTE 说扣费规则「只依赖本关第几步，assert_ 拿不到——这是接口的墙」。这里把本关步数放进 ctx（历史，不是帧），墙就不在了；代价是这条从此不进模型
  • 拟合读数：B = 100 / 100 / 200 / 200 / 250 / 200 / 300 / 400（第 0–7 关），三种取整（floor / ceil / round）里只有 round 在每关都找得到 B（runs/_wb-re86/p_hud2.py）
