World —— 这一局的全部状态。字段就是这一局的对象。

每个字段为什么删不掉，写在 analysis/<字段>.txt（区分检验的见证 + 消融读数）。

    bridges   桥：哪两格之间走得通                   （版面，一关内不变）
    target    目标：踩上就过关。被巡逻压住的那几帧读不出来（None），最后一关过完之后也没有
    player    玩家站在哪一格
    facing    玩家的记号朝哪
    sentries  哨兵：原地不动，盯着正前方那一格
    patrols   巡逻：玩家每真走一步，它沿桥走一步，尽头掉头
    chasers   追兵：醒之前不动；醒了之后每步沿最短路扑向玩家刚才站的那格
    hud       预算带上还剩几格（0..64）

对象层的文件（按目录分组；组的说明取那个子文件夹的 __init__.py）
board

版面：这一关里一步都不会变的那半边世界——落点在哪、哪两格之间有桥、目标在哪。

objects/board/bridge.pyBridge —— 两个相邻落点之间的一段桥。

几何：格坐标与方向。这一类里没有任何世界断言——

objects/geometry/cell.pyCell —— 落点格阵上的一个格（不是像素）。 objects/geometry/dir.pyDir —— 四个正方向之一。

这一局的对象层。一个文件一个类，按子文件夹归类。

objects/parse.py帧 → 世界。全局唯一碰像素的地方。 objects/world.pyWorld —— 这一局的全部状态。字段就是这一局的对象。
pieces

棋子：会动的那半边世界里除了玩家以外的那些。

objects/pieces/guard.pyGuard —— 守卫：玩家以外的棋子。三种（哨兵 / 巡逻 / 追兵），同一种画法、同一个类型。

这一版是怎么剩下来的

对象层里不是 World 字段的四个类型 —— 为什么各自要有

Cell（objects/geometry/cell.py）
  落点阵上的一格（行、列）。把「一格 = 6 像素、相位每关不同」吃掉，上面每一层只认格。
  删掉它 = 回到像素坐标：册子里「6」「3」「相位」这几个数会在每条规则里各抄一份（起点册子里就是这样）。

Dir（objects/geometry/dir.py）
  四个方向。对称（判据 3）提成对象：rev 是对合、perp 对称、自己和自己的反向都不垂直——
  三条都在 Lean 里证了（Derived/DirAlgebra.lean），证不出来就说明提错了。
  「垂直踩进」原来在册子里是 f[0]*d[0] + f[1]*d[1] == 0 在两条概念里各算一次，现在是一个谓词。

Bridge（objects/board/bridge.py）
  无向的一段桥。构造时按 (a, b) 排序，于是「这一对之间有没有桥」只有一种写法——两种写法的坏状态表示不出来。

Guard（objects/pieces/guard.py）
  守卫（格、朝向、醒没醒）。三种共用一个类型（同一种画法）；是哪一种由它住在哪个字段说出来（卡 03 那一刀）。
  第一版带 kind，拆字段之后 kind 这一位不必存了——删的是一个表示，不是一位信息（信息搬进了字段名）。

Player（第一版有，卡 03 拆掉）
  Player(cell, facing) 拆成 World.player 与 World.facing 两个字段，理由见 player.txt / facing.txt。
删掉的那一个字段：nodes（死因：零信息）
World.nodes（第一版有，卡 03 删了）—— 死因：零信息

1. 它记的是什么：哪些格是落点（3×3 块不是底色的那些位置）。
2. 删的凭据（区分检验，卡 03 那一刻就跑得出来，不需要规则）：全部 1126 个读得出的世界里，
   落点集合恰好等于桥的端点集合（runs/_wb-tu93/p5.py：1126 帧，不等的 0 帧）。
   所以「拿掉它，哪一对世界状态从能区分变成不能区分」——一对都没有：给定桥，落点就定了。
3. 删掉 = 信息抹去：World 不再有这一位。代价写在明处：一个不连任何桥的落点现在表示不出来，
   所以 parse 碰到它就抛（「有 N 个落点不连任何桥：World 表示不出孤立落点」），不许悄悄丢掉；
   这一条良构检查被故意弄坏验过一次（run_rules.py --reverse 的「孤立落点」那一行：红）。
4. 卡 06 重量：删掉之后没有任何一条规则跑不起来、拒绝集没有变小（118/120 前后一样）——那一刀没砍错。

注意这和「语料分不开」不是一回事：孤立落点在语料里 0 次，要是哪天出现，parse 会当场读不成，
而不是静悄悄把它当成底色——那正是这一刀要守住的。
