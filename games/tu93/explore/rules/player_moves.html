它说什么

往 d 有桥 ⇒ 落在 player+d、记号朝 d；没桥 ⇒ 位置与记号都不变。

玩家往方向 d 那一格有桥，就挪过去一格、记号转向 d；没桥，位置和记号都不动。

册子里的对应：bridge_gate（中间块是不是桥）+ move_shift（整块平移）+ mark_faces（记号转向）。
对象层把「6 像素」「中间块」「记号在块内哪一格」都吃掉了，这里只剩一句格上的话。

论域：换关那一步归 outcome/reach_target；GAME_OVER 那一步玩家被吃掉，归 outcome/game_over_iff。

它明确不主张什么

  • 守卫怎么动（归 guards/）
  • 记号朝向对守卫有没有影响（没有一条规则读它，见 analysis/facing.txt）

# 规则 move/player_moves —— **定义**

往 d 有桥 ⇒ 落在 player+d、记号朝 d；没桥 ⇒ 位置与记号都不变（整个世界冻住，只有预算照扣）。

import Obj.World
import Obj.Derive.Graph.Linked

namespace Game

/-- 玩家往 d 走，落在哪；没桥返回 `none`（这一步被挡）。 -/
def landing (b : Board) (s : St) (d : Dir) : Option Cell :=
  if linked b.bridges s.player d then some (s.player.move d) else none

/-- 走了之后玩家的位置与记号。 -/
def playerNext (s : St) (d : Dir) : Option Cell → Cell × Dir
  | some q => (q, d)
  | none   => (s.player, s.facing)

end Game

    return step(prev, action, nxt, ctx)


def assert_(prev, action, nxt, ctx=None):
    if scope_(prev, action, nxt, ctx):
        return "NA"
    w, nw, d = world(prev), world(nxt), parse_action(action)
    q = landing(w, d)
    want = (q, d) if q is not None else (w.player, w.facing)
    return "TRUE" if (nw.player, nw.facing) == want else "FALSE"
