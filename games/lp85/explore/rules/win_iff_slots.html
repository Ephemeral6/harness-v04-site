它说什么

这一关结束（关号 +1），当且仅当这一步之后每一个插槽那一格上都是它自己角标色的瓷砖。没有别的旁门：走够步数、点某个隐藏格都不会换关。

它明确不主张什么

不主张换关之后那一关长什么样（那是历史，不是这一帧的函数）；不主张最后一关赢下之后会发生什么。

论域：什么时候它不管

不是点击 → 不管；点中的按钮接线认不出 → 弃权（赢不赢要靠那张置换算）。其余每一次点击都管：换关的那一步用**算出来的**颜色判（下一帧已是新盘），没换关的那一步用**看到的**下一帧判（不依赖接线）。

改版史（从起点册子哪几条来：win_slots_done、no_win_without_slots）

起点册子 win_slots_done v2：词汇只认一种角标色，漏掉了另一色的插槽，把「还没配齐」误判成「已过关」。角标色从此是每个插槽自己的一位（objects/board/slot.py）。
本轮：win_slots_done（配齐 ⇒ 换关）与 no_win_without_slots（没配齐 ⇒ 不换关）合成一个等价——两条单向蕴含拼成一个等价，是卡 05 认可的第一种合并理由。

# Rule/Win/WinIffSlots —— 什么算赢（对应 `rule/win/win_iff_slots.py`）

定义：**每一个插槽那一格上都是它自己角标色的瓷砖**，而且至少有一个插槽。
这是一个**状态**的性质（不是一个转移事件），所以「这个局面赢不赢得了」才问得出来。

Python 那一条是一个等价（过关 ⟺ 装对）；在模型里它变成 `step` 的一个分支：
算出来的颜色满足 `isGoal` 就返回 `won`，否则返回新状态。两半都由语料那一层逐条核
（`Obs/Corpus.lean`：换关的那几步模型必须说 `won`，没换关的那几步模型必须**不**说 `won`）。
-/

import Obj.World

def isGoal (bd : Board) (s : Colors) : Bool :=
  !bd.slots.isEmpty && bd.slots.all (fun sl => s[sl.cell]? == some sl.mark)
