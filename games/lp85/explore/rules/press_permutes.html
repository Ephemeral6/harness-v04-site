它说什么

点中一个按钮，瓷砖的颜色就按这个按钮自己那张固定的置换搬一次——带上的一串整体挪一位、星的环或射线整体转一位、枢纽两两互换、面板环挪一截；置换没提到的格一块都不动。置换只由版面（占位、格阵、按钮）决定，见 derive/wiring.py。

它明确不主张什么

不主张竖条怎么变（归 outside/bar_never_drops）；不主张这一步赢没赢（归 win/win_iff_slots）；不主张换关之后那一帧（那是另一张盘）；接线认不出的按钮不主张「它不动」——那是弃权，不是恒等。

论域：什么时候它不管

不是点击 → 不管（RESET 不进模型）；点空 → 归 click/dead_click；换关 → 归 win/win_iff_slots；接线认不出 → 弃权（有名字、有条数）。

v1（本轮重排）：起点册子里 12 条概念说的是同一句话的不同切片——「点这个按钮，哪几格的颜色搬到哪几格」，按结构（带 / 星 / 枢纽 / 面板）和「动的 / 不动的」各写了一条。它们的论域按按钮的类别互相错开，结论的形状只有一种：一张置换。于是合成一条：置换由 derive/wiring.py 按类别算，规则只说「颜色照它搬、别处不动」。「别处不动」那几条（off_*_static）不再单独存在：本条比的是**整张**颜色表，它们拒得掉的本条都拒得掉。
起点册子这几条被打过的死因（全在接线上，断言体从没改过）：箭头色当方向（竖直箭头拆穿）、链认错（长 20 闭链认成两条长 10；开放蛇形路径没接成环；长 3 竖臂被 MIN_RUN=4 挡掉）、驱动关系认错（一次点击同时转两条互不相连的链；面板按钮按距离配错环）、面板窗口端点算错两次。那些读法现在是 derive/ 里的判别项，它们的反例留在起点册子的 history/ 与 registry.json。

# Rule/Click/PressPermutes —— 点中按钮：颜色按它的接线搬一次（对应 `rule/click/press_permutes.py`）

**这是一个定义，不是一条定理。** 「点中按钮就按置换搬颜色」是对**点中按钮**的定义；
写成待证的定理，就是用它自己证它自己。

第 k 格的新颜色 = 旧的第 `perm[k]` 格的颜色。置换没提到的格——接线里 `perm[k] = k`——原样不动，
所以起点册子里那几条「别处不动」（off_*_static）在这里不是另外的话，是同一个定义的另一半。
-/

import Obj.World

def pressPermutes (b : Button) (s : Colors) : Colors :=
  b.perm.map (fun i => s.getD i 0)
