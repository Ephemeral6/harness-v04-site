写在最前面的缺口（5 条）

  • 接线（哪个按钮搬哪几格）只在 Python 里有一份（derive/wiring.py）；Lean 把它当盘面数据读进来。Lean 核的是「照这份接线搬颜色，逐帧对得上」，不核接线本身是怎么从几何推出来的。
  • 竖条（预算）不进模型：Unsolvable 的准确意思是「不考虑预算、不经过 RESET 也赢不了」；8 关的 _winnable 见证都是真实走法，真实走法没有见底。
  • 「竖条每次填几格」这批语料说不了：一个只把竖条多填了几格的错的下一帧，整本册子拒不掉（seq 192 ← seq 95）。
  • 瓷砖边长打平时取哪个（源码突变体 M21）这批语料测不到：400 帧里从不打平。
  • 接线认不出时规则弃权而不是判错（源码突变体 M07 只让开口条数变少）——看判错之外还要看开口条数。

一块场地上排着一格一格的彩色瓷砖，场地边上有几个箭头按钮。你能做的只有一件事：点。

点中一个按钮，一串瓷砖的颜色整体挪一位——瓷砖本身不动，动的是颜色。 有些格子四角贴着同色的小角标，那是插槽，它要的就是角标那个颜色。 每个插槽都装上了自己要的颜色，这一关就过了。一共 8 关。

左边是点之前，右边是点之后：点中的按钮是黄色的，红圈是点的位置，白框是变了颜色的格。第 0 列那条竖条是这一关的花费。

按钮只有一种用法，但它搬颜色的方式有好几种

每个按钮背后是一张固定的置换：点一下，哪一格的颜色搬到哪一格，一关之内永远一样。 这张置换只由版面决定（哪些格有瓷砖、按钮在哪、指向哪），跟颜色无关。四类按钮各有各的搬法：

带按钮贴着一串首尾相接的格子（一条环、一条直线、一条蛇形路径），点一下整串朝按钮指的方向挪一位。 有时候一下同时带动好几串——独立又没配按钮的那几串会「搭车」。
星一个空的星心、八条射线。切向的把手让所有环一起转一格；径向的把手让八条射线一起往外挪一格（最外一环绕回最里）。
枢纽不属于任何星的那个按钮：每块游离的瓷砖和紧挨着它的那块星上瓷砖互换颜色。
面板一排远离棋盘的按钮，各管一条通向插槽的拐角环上固定的一截；独自一排的那个管全部环、整环转。

点空、花费、赢

  • 点空（没落在任何按钮里）：什么都不变，竖条也不长。
  • 竖条：点中按钮不会让它变短；换到新的一关清零。每次长几格是每关自己的常数，帧上读不出来——所以它不进形式化模型。
  • 赢：这一下之后每个插槽都是自己角标色的瓷砖，就换到下一关。没有别的旁门。
