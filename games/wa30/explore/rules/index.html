规则

这是个什么游戏回放对象规则形式化怎么给别人看

明写的缺口（5 条）

  • 突变体 pick_first_not_last 逐条那一层没红（贴着两颗挑名单最前的 → 逐条判把名单顺序摊开了，预期**测不到**；每关那一层（run_trace）该红）；每关那一层红了
  • 「重置放回开局」不进模型：6 次 RESET 之后那一帧都和开局帧一模一样——没被驳倒，**不构成证明**。
  • 「贴着两颗目标挑甜甜圈名单里最靠后的那颗」只有 2 次见证；另外三种名单口径各错一次。
  • donuts、thieves 两个字段在这批语料里没有「只差它」的一对（分离表分不开）；见证是造出来的孪生局面。
  • 撞盘外（VOID）、走出 16×16 的边：语料里 0 次，「挡」是一句没被检验过的话。

新旧拒绝集

同一批 120 个错的下一帧：旧册 31 条拒掉 85，新规则拒掉 120；旧的拒得掉而新的拒不掉 0 个。

assumed

**说了但不进模型**：写出来、逐条判、打两个数（论域条数、被驳倒几次），但模型的一步不描述它。

reset_to_start 不进模型 |scope| 6 · 判对 6 · 判错 0 · 读不成 0

按 RESET 之后的那一帧，就是这一关开局那一帧（第一次进这一关时看到的那一帧）。

clock

**计时条与时间到**：每走一步用掉一步预算；条是「已用几成」的粗读数；用满就 GAME_OVER。

bar_never_rises 推论 |scope| 1500 · 判对 1500 · 判错 0 · 读不成 0

同一关里任何一步，计时条亮着的格数不会变多。

time_up 定义 |scope| 1500 · 判对 1500 · 判错 0 · 读不成 0

没过关的前提下，这一关的已用步数走到预算的那一步 GAME_OVER；差一步都不会。

timer_tick 定义 |scope| 1500 · 判对 1500 · 判错 0 · 读不成 0

同一关里每按一次键（方向、ACTION5 都算，撞墙、打空也算）这一关的已用步数加一；条上亮着的格数 = 64 − round(64·已用步数 / 这一关的预算)。

goal

**什么算赢**：一整步（玩家那半步 + 鼹鼠那半步）走完之后，

level_up 定义 |scope| 1515 · 判对 1515 · 判错 0 · 读不成 0

一整步走完之后，手上没攥着、没有鼹鼠驮着货、每一颗甜甜圈都坐在容器格上，这一步就换关；只要有一样不成立，这一步就不换关。

moles

**鼹鼠怎么走**：玩家动完之后，场上的帮手和贼按名单轮流动一下——偷、驮、放、找路。

moles_act 定义 |scope| 1346 · 判对 1346 · 判错 0 · 读不成 0

玩家动完之后，鼹鼠按名单轮流动一下（帮手先、贼后；一只偷到手后，同皮排在后面的这一步不动）。轮到的那只：驮着的货已经到家（帮手：容器格；贼：巢格）就放下、不动；驮着没到家就沿最短路（人和货两格一起走，终点是货落进一格空着的家）挪一格；空手而贴着目标就偷、不动；空手不贴着就沿最短路朝最近的目标挪一格。最短路有好几条时按「左、右、上、下」的次序展开取第一条。目标：不在自己家里的货；别人驮着的只有贼会抢、而且只抢帮手的；攥在玩家手里的也只有贼会抢。

player

**一步怎么走（玩家这一侧）**：按了一个键之后，玩家块挪不挪、头朝哪、手上那颗怎么样。

drag 定义 |scope| 562 · 判对 562 · 判错 0 · 读不成 0

攥着货时按方向键：头不转；人要去的格（可以是货刚让出来的那格）站得上去且空着、货要去的格（可以是人刚让出来的那格）进得去（地面 / 容器 / 纯内芯 / 围栏）且空着——两样都成立就一起挪一格，否则人和货都不动。挪完那颗货仍在正前方。

player_stride 推论 |scope| 1500 · 判对 1500 · 判错 0 · 读不成 0

同一关里任何一步，玩家块要么不动，要么挪到上下左右相邻的一格。

press 定义 |scope| 191 · 判对 191 · 判错 0 · 读不成 0

按 ACTION5 人不动、头不转，而且：攥着就松手；手空而正前方有货就攥住它（只有贴着正前方的贼能在同一步把它夺走）；正前方是贼就把它打掉；都不是就什么也不发生。

walk 定义 |scope| 747 · 判对 747 · 判错 0 · 读不成 0

手空时按方向键：头一定转向那一边；前面那格站得上去（地面 / 容器 / 纯内芯）且没有甜甜圈、没有鼹鼠，就挪过去一格，否则原地不动。
