形式化

每一关走得通还是走不通，用 Lean 证出来。结论在最前。
这是个什么游戏 回放 对象 规则 形式化 怎么给别人看

明写的缺口（6 条）—— 摆在最上面，不藏

  • 「不可做」只有一把钥匙（墨用光了、颜色又不对）；技能要求至少两把理由不同的，第二把（挡住了）没写
  • 配对的「颜色集合」那一半这批语料考不动：反向测试把配对改成不看颜色，判错 0——罐子从没落在配不上的靶心上
  • 看不见的底色按「不挡路」算（明写的假设）：Python 倚仗它 32 步、被驳倒 0 次；整关拼盘之后仍看不见的格同样按这一条
  • RESET 不进模型：「放回第 0 关开局」在这批语料上被驳倒的机会只有 1 次（没被驳倒不构成证明）
  • 预算 60 下是外推（每关最多见到第 23 下），竖条见底会怎样语料 0 次
  • 点在两颗菱形重叠处：Lean 取 anchors 里第一颗、Python 取排序后第一颗，语料 0 次，两边在这一处可能不同

「逐帧核过」= 只有开局那一帧是观测给的，后面每一帧都是模型自己算出来、再和看到的那一帧比（L<n>_trace）； 「走得通」的见证就是认证那一段真实走法加过关那一脚（L<n>_winnable）。另一段成绩单不认证，只当更多的核对，不当见证。

六关都有人走通过，所以这里没有一条「走不通」。模型里没有 RESET：任何「走不通」的准确意思都是「不经过重置就走不通」。

它怎么来的：钥匙与三条防线

「走不通」的骨架只证一次（unsolvable_of_invariant：一个每步都保持、又和「赢」矛盾的性质 ⇒ 任何点击串都赢不了）， 证明里没有枚举、没有搜索，和盘面多大无关。这一局给了一把钥匙：墨用光了、颜色又不对（NoInk）。 每把钥匙配一张只差一处的盘：stuck_unsolvable（套得上 ⇒ 赢不了）· twin_winnable（只把靶环颜色换对，一步就赢）· twin_closed_at_start（不是一开始就通）· twin_not_noInk（钥匙的前提在它身上真的不满足）。 看 Proof/Reachable.lean

第二把钥匙没写——见最上面的缺口。
