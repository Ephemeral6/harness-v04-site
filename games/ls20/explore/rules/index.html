key

**这一组管：钥匙怎么变。**

key_holds这一步没踩到任何装置（包括撞墙、撞锁那一步）时，钥匙的图样与墨色都不变。推论 开口 1257 · 判错 0 key_recolors这一步踩到染色物件时，钥匙墨色按 12→9→14→8→12 换下一档，图样不变。定义 开口 46 · 判错 0 key_reshapes这一步踩到非十字开关时，钥匙换成六环上的下一种形状（朝向保持），墨色不变。定义 开口 50 · 判错 0 key_rotates这一步踩到十字开关（静止的走进去，或巡逻的撞上来）时，钥匙图样顺时针转 90°，墨色不变。定义 开口 70 · 判错 0
move

**这一组管：按一个方向键，玩家最后停在哪一格。**

blocked按方向键，目标格是墙、或是钥匙对不上的门时，玩家原地不动。定义 开口 41 · 判错 0 slide按方向键，目标格贴着弹簧线时，玩家先进去，再沿线推的方向一格格滑，下一格不是地板、或是门心时停下（不拐弯、不滑进门）。定义 开口 71 · 判错 0 walk按方向键，目标格是普通地板（不是门、不贴弹簧线）时，玩家恰好走进那一格。定义 开口 1312 · 判错 0
outcome

**这一组管：什么算赢、什么算砸。**

door_consumed钥匙对上、走进的门不是最后一道时：玩家站进门心，这道门从盘上消失，别的门一道不少。定义 开口 5 · 判错 0 last_door_wins按方向键之后关卡号加一，当且仅当目标格是门心、钥匙（形状与颜色）对上、而且它是盘上最后一道门。定义 开口 1448 · 判错 0 out_of_energy能量为 0 时再按方向键：目标格是补给 ⇒ 照常走进去、能量回满、不掉命；否则 ⇒ 命恰好少一条、能量回满、关卡号不变。定义 开口 12 · 判错 0
unmodeled

**这一组：说了，但明说不进模型。**

reset_restarts_game按 RESET 之后，下一帧就是整局第一帧（第 0 关开局）的样子，关卡号回到 0。不进模型 开口 2 · 判错 0 restart_to_start能量为 0 再按方向键而掉了命之后，下一帧就是这一关开局那一帧的样子（玩家、钥匙、装置、补给、门、能量都一样），只有命少一条。不进模型 开口 10 · 判错 0
world

**这一组管：世界自己怎么回应一步棋。**

board_holds普通的一步前后，两帧都看得见的格，是不是地板一格不变；两帧都看得见的弹簧线一根不变。不进模型 开口 1434 · 判错 0 devices_stay普通的一步里，不在巡逻线 / 绕圈上的十字开关、非十字开关、染色物件、补给：前一帧看得见而下一帧看不见的，只能是被玩家盖住了或进了雾；下一帧新看见的，只能是前一帧玩家盖着的那一格（补给除外——补给被盖住就是被吃了）或前一帧在雾里的格。推论 开口 1434 · 判错 0 energy_cost普通的一步之后能量 = 能量 − 这一关的单价（撞墙也扣）；撞到锁着的门不扣；登记为「踩开关免费」的那一关，踩到十字开关那一步不扣；减到 0 为止。定义 开口 1390 · 判错 0 fog同一关之内的一步，前后两帧有没有迷雾，恰好由关卡号决定（登记在 level_table.FOG 的关有，其余没有）。定义 开口 1446 · 判错 0 goals_hold普通的一步如果不是开门，两帧都看得见的门完全一样（位置和要的钥匙）。推论 开口 1424 · 判错 0 lives_hold能量不为 0 时的一步，命数不变。推论 开口 1434 · 判错 0 orbit有绕圈染色物件的关里，玩家这一步动了，它就沿登记的圈走恰好一格；玩家没动，它不动。定义 开口 490 · 判错 0 patrol有巡逻线的关里，玩家这一步动了，线上的装置就沿线走恰好一格（到端点掉头）；玩家没动（撞墙、撞锁），它一格不动。定义 开口 919 · 判错 0 refill普通的一步落脚在补给上时，能量回到满格（42）。定义 开口 39 · 判错 0
