它说什么

同一关之内，每一个点击（点面板、交卷作废、交卷挪件都算）让顶栏掉 pay 格：节奏 1 的关 pay = 1；节奏 2 的关 pay = 本关已走步数 k 的奇偶（k 从 0 数，k 偶数免费）。

关内每一个点击，顶栏按这一关的付费节奏掉格：节奏 1 每下掉一格；节奏 2 本关第 1、3、5… 下免费、第 2、4、6… 下掉一格。

论域：什么时候它不管、交给谁

RESET 不管（归 `说了但不进模型/reset_restarts`）；换关 / 打完整局的那一步不管（下一帧是下一关或终局画面，归 `什么算赢/fit_clears_level`）。

它明确不主张什么

**不主张节奏为什么是这样**：第 0–4 关节奏 1、第 5–6 关节奏 2，是按关号记的一张语料事实表（RATE），帧上读不出来；换一张没见过的卡，第一次进一个新关时这张表可能先错一次。「本关已走几步的奇偶」也是帧上读不出来的一位（顶栏只看得见花掉几格，k 是 2s 还是 2s+1 读不出），由上游 meta 数出来交给规则（ctx.k）。不主张顶栏见底之后会怎样——本批语料最少还剩 22 格。不主张关内 RESET 之后 k 从几数——语料里关内 RESET 0 次。

-- IDENTITY: definition

**定义**：关内每一下点击，顶栏掉 `pay` 格；`phase` 翻一下。
节奏表 `rateOf` 按关号查（第 5、6 关节奏 2，其余节奏 1）——**语料事实表，帧上读不出**；
这一份是独立写的一张表，和 Python 那张由逐条对账核。
-/
import Obj.Frame.Layout
import Obj.Frame.World

namespace Game

def rateOf : Nat → Nat
  | 5 => 2
  | 6 => 2
  | _ => 1

/-- 这一下掉几格。节奏 1：每下 1 格；节奏 2：本关第奇数个动作（`phase = true`）掉 1 格，偶数个免费。 -/
def pay (lvl : Nat) (phase : Bool) : Nat :=
  if rateOf lvl = 1 then 1 else if phase then 1 else 0

def upkeep (L : Layout) (w : World) : World :=
  { w with counter := w.counter - pay L.level w.phase, phase := !w.phase }

end Game
