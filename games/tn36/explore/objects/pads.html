为什么删不掉它（读数在最前）

字段 pads（objects/board/pads.py）—— 为什么它删不掉

1. 它记什么：这一帧**看得见**的花格（件压着的那一格读不出是不是花格，不算）。
2. 谁读它（点名）：piece_follows_program（终点能不能停、件离开后露出什么）；fit_clears_level 经 derive/outcome 间接 import 它，
   但过关的判定在查花格之前就定了，所以不读——点名多点了一个，消融把它纠正过来。
3. 抹掉它，哪几条规则的判决会变（真跑）：
     抹成常量（第 0 关那一帧的值：空集）：piece_follows_program 5。
     错位：piece_follows_program 21。
4. 分离表：分不开（239 组）。理由同 piece.txt：它只随件的挪动而变（遮挡），是 ③。

一对具体的世界：第 5 关里件在 (6,0)、看得见的花格 {(0,5),(4,4),(6,5)}，交 E E E E N N 件挪到 (4,4)；
把花格抹成空集，这一道就读成「终点不是花格 → 作废」。第 5 关 seq 74（E E E E N S，终点 (6,4) 普通格）与 seq 77
（E E E E N N，终点 (4,4) 花格）只差终点落不落在花格上，一个不动一个挪——分开它们的正是这一位。结论：留。

它是什么

`Pads` —— 花格：件可以**停下来**的格（色 11 与底色交错的 4×4 棋盘纹）。

一道程序走完，终点落在花格上件才照走；落在普通格上整道程序作废（规则 `submit_runs_program`）。

**为什么单独成一个字段，不并进 `Board`**：花格是盘上画着的，本来不会动；
但件压在花格上时那 16 个像素全被件盖住，**帧上读不出那一格是不是花格**。
所以这一帧能说的只是「**看得见的**花格有哪些」，它会随件挪走而多出一格。
把它并进 `Board` 就等于声称盘在一关之内会变——那是读法的毛病，不是世界的。

    cells   这一帧看得见的花格（件底下那一格不算：读不出）

# Pads —— 花格：件可以停下来的格。对应 `objects/board/pads.py`。

**两个口径，写在明处**（和 Python 那边不一样的地方就在这里）：

    Python 的 `World.pads`   这一帧**看得见**的花格——件压着的那一格读不出来，不算
    Lean 的 `Layout.pads`    放在版面里、step 碰不到；取值有两种口径（`Obs/Replay.lean` 分开存）：
                               逐条那一层用「这一帧看得见的」
                               每关那一层用「整关取并集」——件起步时压着的那一格也算花格

「看得见的花格」在 Lean 里是算出来的：版面的花格减去件盖住的格（`visiblePads`）。
-/
import Obj.Geometry.Form

namespace Game

abbrev Pads := List Cell

/-- 这一刻看得见的花格：版面的花格里，没被件盖住的那些。 -/
def visiblePads (pads : Pads) (piece : Form) : Pads :=
  pads.filter fun x => !(piece.footprint.contains x)

end Game
