为什么删不掉它（读数在最前）

字段 layout（objects/frame/layout.py = board + toolbox + controls + scenery）—— 为什么它删不掉

1. 它记什么：这一关的版面——盘（行列、墙、记号、插槽空腔）、底栏给了哪几种指令、命中盒、其余画面的指纹。
   卡 03 由四个同生共死的字段合成（四个在 581 个世界上分组完全相同，只在换关时一起变）。
2. 谁读它（点名）：panel_follows_clicks（命中盒）、piece_follows_program（盘、底栏、命中盒）、fit_clears_level（同上）、
   layout_stays（全部）；counter_pays / reset_restarts 经 derive/click 间接 import，但只用 is_reset / xy，不读版面。
3. 抹掉它，哪几条规则的判决会变（真跑）：
     抹成常量（第 0 关的版面）：panel_follows_clicks 200、layout_stays 53、fit_clears_level 16、piece_follows_program 5。
     错位：panel_follows_clicks 43、fit_clears_level 11、layout_stays 15、piece_follows_program 5。
   四个部件各自错位（卡 06 要重量卡 03 那一刀）：
     board    fit_clears_level 11、layout_stays 15、piece_follows_program 4
     toolbox  fit_clears_level 4、layout_stays 13、piece_follows_program 2
     controls panel_follows_clicks 43、fit_clears_level 4、layout_stays 3、piece_follows_program 1
     scenery  layout_stays 13（只有看门的那一条读它——它本来就是报警器，不是动力学）
4. 分离表：分不开（239 组）。③：这一局每一关只有一张版面，换关时件、面板一起换。

卡 03 合并砍错了吗：没有。四个部件每一个都有规则在读，合并没有抹掉信息；
而它们在语料里从不单独变化，拆回四个字段只会还原成四个「分不开」。该拆的信号（规则里对同一字段的不同取值走不同分支，
而那个分叉的依据本该是对象上的一位）没有出现。结论：留，不拆。

它是什么

`Layout` —— 这一关的**版面**：盘、底栏给的指令、命中盒、其余画面。一关之内一格不变。

卡 03 合出来的：`board` / `toolbox` / `controls` / `scenery` 四个字段在整批语料上
**同生共死**——分离表里四个都「分不开」、分组数都是 239，它们只在换关那一步一起变
（见 `analysis/field_split.txt` 卡 03 那两段、`analysis/record.txt` 第一轮）。
四个字段说的是同一件事：**这是哪一关的版面**。所以 World 里只留一个字段；
四个部件照旧各是一个对象（组合分解：版面 = 盘 + 底栏 + 命中盒 + 其余画面），规则按部件读。

这一刀**没有抹掉任何信息**（四个部件原样在），抹掉的是「它们是四件独立的事」这个说法。
它会不会砍错，卡 06 拿消融重量：要是有规则只读其中一块、而那一块在别处独立变化，就该拆回去。

# Layout —— 这一关的版面：盘、花格、底栏、命中盒、其余画面，外加上游给的关号。对应 `objects/frame/layout.py`。

**版面不是 `World` 的字段**：`step` 的类型是 `Layout → World → Act → Res`，它拿得到版面、却交不出新的版面——
「一关之内版面不变」于是**不用证，它根本表示不出来**（卡 08）。代价：查一格地形多穿一层。

和 Python 的两处不同，都写在明处：
  · 花格（Python 里是 World 的字段 `pads`）搬到了这里，理由见 `Obj/Board/Pads.lean`；
  · 多了 `level`：它是上游（meta）给的关号，节奏表按它查（`Rule/Response/CounterPays.lean`）。
    Python 那边同一个数从 ctx 读，不进 World——两边都不把它当成帧上读出来的东西。
-/
