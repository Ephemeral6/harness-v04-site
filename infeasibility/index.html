紧预算版

一排液槽，按钮一次搬「隔条厚度」那么多。不可赢的一半，靠的是两种证书：一种是流量下界，预算正好比下界少一步；另一种是步长余数。

读数（自述级：子 agent 跑，没有容器隔离）：普通 agent 两轮都 6/6；带框架的一轮也是 6/6，而且每道不可赢关都附了一份过核的证书。⇒ 按冻结判据，构造失败：普通 agent 就做得出来。两臂之间只剩一个差别，就是证据的形态。

对称闩版

在紧预算版上加一条发给作答方的说明里没有写的规则：闩。两侧的槽都恰好满时，点墙身就松开，之后这条隔条一次只搬 1 格。可赢的关必须用闩；不可赢的关，闩永远松不开。

读数（自述级）：普通 agent 两轮分别 3/6、0/6；带框架 3/6。带框架的 B 套交了 6 份证书，其中 3 份编译干净，讲的却是一件在这个世界里为假的事，因为它归纳出的模型里没有闩。⇒ 两臂都没做出来，构造失败。给框架的方法册补一条硬规则再跑（硬规则版），两轮是 3/6、6/6，仍然失败。

出处：session-log/2026-09-26-c9-arms.md。

多米诺闩版

闩的触发改成不对称：左边的槽恰好满、右边的槽恰好空。这样，松开一个闩会改变下一个闩的处境，可以串成多米诺链。12 个槽，链长 3 或 4；不可赢的那一关，只比孪生多改一处墙高，链首的闩就再也松不开。

读数（自述级）：规则维度成立：4 个拿不到规则的会话，没有一个松开过闩，两轮都是 0/6。推理维度不成立：拿到完整规则的会话两轮都是 6/6，它们用约束求解或窗口搜索，自己推出了余数不变量。算法求解器（宽搜 + A*，每关 30 分钟）已跑完 12/12 关：0 关判对，12 关到上限仍是 unknown。带框架的 A 套，按补充规则自查时发现一处没解释的颜色，于是一个裁定都没交；B 套 6/6 判对：3 道可赢关真赢了，3 道不可赢关各附一份 Lean 证书（3 份都由我们独立重编核过）。⇒ 按冻结判据，「足够复杂」不成立。

出处：session-log/2026-09-27-c10-arms.md。
